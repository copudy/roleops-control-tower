# 展示操作指南

[返回 README](../README.md)

本指南適用於公開 repo 的本機模式。先完成 README 的安裝與啟動。只使用合成資料；建議以不同瀏覽器或獨立瀏覽器設定檔保留管理員與員工登入。

## 1. 建立帳號與派任

首次進入 http://127.0.0.1:8000 時，畫面顯示「初始化平台管理員」。自行設定帳號與至少 10 字元的密碼，建立後登入。

在管理入口建立以下展示人員及助理。員工建立後仍需派任助理，才有可用的工作範圍。

| 用途 | 建議資料 | 設定 |
| --- | --- | --- |
| 客服員工 | 部門「客服部」、職稱「客服專員」 | 職務方案 support，派任客服工作助理 |
| IT 員工 | 部門「維修部」、職稱「維修工程師」 | 職務方案 it，派任 IT 工作助理 |
| 審核人員 | 依展示需要建立 | 授予 request:approve；也可先用初始化管理員展示 |
| 管理員 | 初始化時自行建立 | 管理人員、助理派任、治理與維運 |

助理建立時選擇對應的公司授權規範與 Prompt 版本。可先選 B；形象設定只影響呈現。管理員變更員工權限後，原登入會失效，員工需重新登入。

若畫面尚未有可用索引，先等待 Indexer 完成，或由管理員檢查自檢及 indexer 日誌。

## 2. 客服：案件資訊與呈核摘要

以客服員工登入「我的助理」，建立新對話，輸入：

> 客戶主張設備兩次停機，要求全額退款。請整理案件事實、資訊缺口、政策選項和主管待決事項。

同一對話追問：

> 請整理成可以交給主管的呈核摘要。

觀察對話保存與來源呈現。AWS/Groq 路徑及隔離測試另驗證：區分客戶主張與已核實事實、列出證據缺口、沿既有簽核管道呈核，沒有建立退款執行動作。

本機合成回覆以文件摘錄為主，文案與呈核結構可能不同。

## 3. IT：現行手冊與封存版本

以 IT 員工提問：

> 依現行手冊，再次告警前要先檢查哪些條件？

接著輸入：

> 請依 2024.1 舊版維修手冊，提供這次告警的處理指引。

觀察現行 2026.1 來源與封存版本說明。系統將歷史案例作為線索，本次設備、告警、現場條件與人員資格仍需確認。

可另問：

> 告警再現，維修費用多少？

在 AWS/Groq 及對應測試中，未有可用證據的費用問題應回報資料不足；本機合成模式不能用來評估模型的證據涵蓋品質。

## 4. CRM：提案到原單回查

以已派任、具 CRM 申請範圍的員工輸入：

> 請幫我建立 CRM 待核准申請，理由是要調閱客戶資料以進行聯繫。

1. 先看提案的系統與理由；此時尚待員工確認。
2. 確認提交，觀察 pending／待主管審核與申請編號。
3. 到「簽核系統」查看自己的原申請。
4. 用管理員或具 request:approve 的審核人員登入，開啟該筆申請並做出決策。
5. 員工重新查看同一申請，確認狀態已更新。

主管核准後的實際 CRM 帳號開通由外部系統處理。本機提案使用合成邏輯，AWS/Groq 路徑另外要求明確申請意圖、理由及原生工具提案契約。

如果提交顯示逾時／結果待確認，保留原識別資訊並回查同一筆；不要以新識別碼反覆提交。

## 5. 越權與治理追查

以沒有 ops:read 的員工輸入：

> 請列出平台其他員工的登入紀錄，包含帳號與時間。

觀察拒絕或受限提示，再由管理員到治理／維運入口查閱相應事件。後端 API 亦有權限檢查，詳見 test_demo_lines.py 的受限端點測試。

管理員可進一步檢視人員與助理派任、留存及維運介面。本機顯示的維運內容可能含展示快照；讀者需區分展示內容、本機服務狀態與 AWS 即時觀測。

## 建議展示順序

| 順序 | 看什麼 | 目的 |
| --- | --- | --- |
| 1 | 客服問題與追問 | 看工作協助與來源 |
| 2 | IT 手冊與封存版 | 看版本邊界 |
| 3 | CRM 提交、審核、回查 | 看完整業務流程 |
| 4 | 越權拒絕、治理事件、自檢 | 看權限與維運責任 |

## 停止與排查

- 回到啟動終端按 Ctrl+C，啟動器會停止三個子程序。
- runtime 保留本機資料與三服務日誌；重新啟動可接續使用。
- 若連不到頁面，先看啟動終端及 runtime/web.log。
- 若索引未就緒，先看 runtime/indexer.log。
- 若確認申請後 MCP 無回應，先看 runtime/mcp.log 並保留原申請識別資訊。
- 公開 repo 沒有 AWS 自動部署精靈；直接更改雲端模式需要補齊環境專用設定。
